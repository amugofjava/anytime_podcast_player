# 0002 - Transcode Progress, ID3 Tag Embedding, Process-Kill Recovery, and Selective Auto-Download

## Context
When non-MP3 podcast audio (such as M4A or AAC) finishes downloading, native FFmpeg is invoked to transcode the audio into MP3. Previously, the app remained at 100% download state with no visual indication of transcoding progress, and external audio players displayed raw CDN hash codes rather than legitimate episode titles because ID3 tags were not populated. Furthermore, if the app process was terminated by the Android OS during download or transcoding, unfinished tasks lacked cold-start recovery. Lastly, users required automatic detection of new episodes upon app launch with selective per-podcast auto-downloading into their respective directories.

## Decision
1. **Transcoding State & Progress**: Introduce a distinct `DownloadState.converting` state in the domain model. When FlutterDownloader completes (100%), switch state to `converting` and display transcode progress or active conversion animation in `DownloadButton` and `TransportControls`, transitioning to `downloaded` (check icon) only when MP3 transcoding finishes.
2. **Audio Metadata Tags (ID3)**: Embed ID3v2 metadata (`title`, `artist`, `album`, `date`) during FFmpeg conversion using `-metadata title=... -metadata artist=... -id3v2_version 3`, guaranteeing that external players and in-car systems display the proper episode title and podcast title.
3. **Startup Recovery**: On cold start of `MobileDownloadService`, inspect the episode repository for any tasks left in `converting` or downloaded non-MP3 files that require transcoding, automatically resuming conversion in the background without user intervention.
4. **Selective Auto-Download**: Provide a global auto-download toggle and a selective podcast subscription picker in Settings (`auto_download_podcasts`). Upon app startup and background library refresh, detect newly published episodes for selected podcasts and enqueue downloads into `<Download Root Directory>/<Podcast Directory>/`. Enforce Wi-Fi-only restriction (respecting mobile data preferences) and cap each podcast to the latest 1-2 new releases per refresh to prevent storage exhaustion.
